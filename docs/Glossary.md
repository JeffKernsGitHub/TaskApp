## Glossary Entries

### A

#### Actuator (Spring Boot Actuator)
* **Definition:** A Spring Boot subsystem that provides production-ready operational telemetry, metrics, auditing, and health check endpoints without manual instrumentation.
* **TaskApp Implementation:** Exposed under `/actuator/health` and `/actuator/metrics`. NGINX proxies these endpoints to the backend, enabling real-time telemetry dashboards in the Angular frontend and Kubernetes liveness/readiness probes.
* **References:** [System Design Document § 8.1](System%20Design%20Document.md#81-spring-boot-actuator-telemetry), [backend/README.md](../backend/README.md)

#### Angular 22
* **Definition:** A TypeScript-based open-source frontend web framework developed by Google, emphasizing component-based UI development, fast compilation, and optimized runtime performance.
* **TaskApp Implementation:** The core framework for the Single Page Application (`frontend/`), utilizing standalone components, reactive signals, and zoneless change detection.
* **References:** [frontend/README.md](../frontend/README.md), [System Design Document § 4.1](System%20Design%20Document.md#41-frontend-architecture-frontend)

#### Angular Material 3
* **Definition:** Google's component library implementing the Material Design 3 specification for Angular applications.
* **TaskApp Implementation:** Supplies theme tokens, form fields, buttons, dialogs, snackbars, and CDK drag-and-drop primitives in the TaskApp frontend (`frontend/src/styles.css`).
* **References:** [frontend/README.md](../frontend/README.md)

#### Angular Signals
* **Definition:** A reactive programming model introduced in Angular that provides fine-grained, synchronous reactivity with automatic dependency tracking, eliminating manual subscription teardowns.
* **TaskApp Implementation:** Managed via `signal()`, `computed()`, and `effect()` in `AuthService`, `TaskService`, and `ThemeService` to coordinate user authentication and task filtering state deterministically.
* **References:** [System Design Document § 2 (ADR-002)](System%20Design%20Document.md#adr-002-angular-22-standalone-components-with-reactive-signals-over-ngmodules), [frontend/README.md](../frontend/README.md)

### B

#### BCrypt
* **Definition:** A password-hashing mathematical function based on the Blowfish cipher, featuring an adaptive salt and computational work factor to resist brute-force and rainbow table attacks.
* **TaskApp Implementation:** Spring Security's `BCryptPasswordEncoder` computes and validates salted hashes stored in the `tasks.users.password_hash` column.
* **References:** [System Design Document § 6.2](System%20Design%20Document.md#62-authentication--authorization-flow), [Data Dictionary § 3.1](Data%20Dictionary.md#31-table-tasksusers-user-identity--credentials)

#### Bearer Token
* **Definition:** An HTTP authentication token format specified in RFC 6750, wherein possession of the token grants access to protected resources without requiring separate credentials per call.
* **TaskApp Implementation:** Transmitted in the HTTP header `Authorization: Bearer <jwt_token>` by Angular's `authInterceptor` on all calls directed to `/api/v1/*`.
* **References:** [System Design Document § 3.3](System%20Design%20Document.md#33-end-to-end-request--authentication-lifecycle), [backend/README.md](../backend/README.md)

---

### C

#### Cascading Delete (`ON DELETE CASCADE`)
* **Definition:** A relational database constraint rule specifying that when a parent table row is deleted, all matching foreign key child rows are purged automatically by the database engine.
* **TaskApp Implementation:** Enforced on the `tasks.tasks.user_id` foreign key referencing `tasks.users(id)`. Deleting a user purges all associated tasks atomically, preserving referential integrity.
* **References:** [Data Dictionary § 3.3](Data%20Dictionary.md#33-referential-integrity--foreign-key-matrix), [database/ddl/task-schema.sql](../database/ddl/task-schema.sql)

#### CNCF Kustomize
* **Definition:** A template-free Kubernetes configuration management tool adopted by the Cloud Native Computing Foundation (CNCF) that customizes YAML manifests via overlay patches.
* **TaskApp Implementation:** Located in `deploy/k8s/`, defining reusable `base/` resources (PostgreSQL, Backend, Frontend, Ingress) and environment overlays (`overlays/dev/`, `overlays/prod/`).
* **References:** [deploy/k8s/README.md](../deploy/k8s/README.md), [System Design Document § 7.2](System%20Design%20Document.md#2-kubernetes-cloud-native-manifests-deployk8s)

---

### D

#### Database Index (B-Tree)
* **Definition:** A self-balancing search tree data structure that allows database engines to perform logarithmic-time searches, range queries, and ordered traversals on indexed table columns.
* **TaskApp Implementation:** Defined in PostgreSQL on `tasks.tasks(user_id)`, `tasks.tasks(status)`, and `tasks.tasks(due_date)` to optimize user filtering, Kanban swimlane queries, and calendar sorting.
* **References:** [Data Dictionary § 3.4](Data%20Dictionary.md#34-index-catalog--performance-justifications), [System Design Document § 5.2](System%20Design%20Document.md#52-schema-constraints--optimizations)

#### DDL Validation Mode (`ddl-auto: validate`)
* **Definition:** A Hibernate ORM configuration mode where the application checks that JPA entity mappings match the database schema at startup, aborting boot if any discrepancies are found without executing DDL modifications.
* **TaskApp Implementation:** Configured via `spring.jpa.hibernate.ddl-auto: validate` in `application.yaml` to prevent automatic schema drift and ensure version-controlled DDL determinism.
* **References:** [System Design Document § 2 (ADR-004)](System%20Design%20Document.md#adr-004-strict-relational-schema-governance--jpa-validation-mode), [backend/README.md](../backend/README.md)

---

### E

#### ENUM (PostgreSQL User-Defined Type)
* **Definition:** A custom PostgreSQL composite data type storing a static, ordered set of text labels internally encoded as efficient 4-byte integers.
* **TaskApp Implementation:** Three custom ENUM types in the `tasks` schema: `task_status` (`TODO`, `IN_PROGRESS`, `DONE`), `task_priority` (`LOW`, `MEDIUM`, `HIGH`), and `user_role` (`USER`, `ADMIN`).
* **References:** [Data Dictionary § 2.2](Data%20Dictionary.md#22-custom-user-defined-types-enum-catalog), [database/README.md](../database/README.md)

---

### F

#### Functional Guards (`CanActivateFn`)
* **Definition:** Angular route guards defined as lightweight, composable functions using `inject()` rather than class-based injectable providers.
* **TaskApp Implementation:** `authGuard` verifies user authentication and redirects unauthenticated users to `/login`; `adminGuard` restricts administrative dashboards to callers possessing the `ADMIN` role.
* **References:** [System Design Document § 4.1](System%20Design%20Document.md#41-frontend-architecture-frontend), [frontend/README.md](../frontend/README.md)

#### Functional Interceptors (`HttpInterceptorFn`)
* **Definition:** Composable HTTP middleware functions in Angular that inspect and transform outbound HTTP requests and inbound responses.
* **TaskApp Implementation:** `authInterceptor` automatically attaches the JWT Bearer token to API calls, and `errorInterceptor` intercepts RFC 9457 Problem Details errors to render user-friendly toast alerts.
* **References:** [System Design Document § 4.1](System%20Design%20Document.md#41-frontend-architecture-frontend), [frontend/README.md](../frontend/README.md)

---

### H

#### HikariCP
* **Definition:** A high-performance, lightweight JDBC connection pool for Java applications that maximizes connection throughput with minimal bytecode footprint.
* **TaskApp Implementation:** Configured in `application.yaml` with a 10-connection pool, 20-second connection timeout, and 30-minute maximum connection lifetime to support Java 25 Virtual Threads.
* **References:** [System Design Document § 5.4](System%20Design%20Document.md#54-hikaricp--hibernate-configuration-tuning), [backend/README.md](../backend/README.md)

#### HTML5 PushState Routing (`try_files`)
* **Definition:** A client-side routing strategy using the HTML5 History API (`pushState`) where the browser URL changes without triggering full page reloads, requiring the web server to route unmapped requests back to `index.html`.
* **TaskApp Implementation:** Configured in `frontend/nginx/nginx.conf` via `try_files $uri $uri/ /index.html;`, ensuring deep links (e.g. `/tasks/kanban`) resolve correctly without returning 404 errors.
* **References:** [System Design Document § 4.2](System%20Design%20Document.md#42-edge-reverse-proxy-frontendnginx), [frontend/README.md](../frontend/README.md)

---

### I

#### Identity Column (`GENERATED BY DEFAULT AS IDENTITY`)
* **Definition:** The SQL:2003 standard compliant mechanism for auto-incrementing surrogate primary keys, preferred over legacy PostgreSQL `SERIAL` types.
* **TaskApp Implementation:** Used for `tasks.users.id` and `tasks.tasks.id` primary keys backed by underlying PostgreSQL 64-bit sequences.
* **References:** [Data Dictionary § 2.3](Data%20Dictionary.md#23-database-sequences-catalog), [database/ddl/task-schema.sql](../database/ddl/task-schema.sql)

#### Insomnia REST Workspace
* **Definition:** An open-source desktop API testing client workspace containing pre-configured HTTP requests, environment variables, authentication configs, and verification scripts.
* **TaskApp Implementation:** Exported in `insomnia/insomnia-export.Tasks` to provide ready-to-run test collections for CRUD operations, JWT login, and RBAC endpoint validation.
* **References:** [insomnia/README.md](../insomnia/README.md), [README.md](../README.md#documentation--reference-index)

---

### J

#### Jakarta Bean Validation
* **Definition:** A Java standard specification (Jakarta Validation 3.0 / Hibernate Validator) enabling declarative constraint validation on Java models via annotations.
* **TaskApp Implementation:** Annotations (`@NotBlank`, `@Size`, `@NotNull`, `@FutureOrPresent`) validate incoming record payloads (`CreateTaskRequest`, `UpdateTaskRequest`, `RegisterRequest`) in Spring Boot controllers before service execution.
* **References:** [System Design Document § 4.3](System%20Design%20Document.md#43-backend-service-architecture-backend), [backend/README.md](../backend/README.md)

#### Java 25
* **Definition:** The LTS-track Java Development Kit and runtime environment powering the TaskApp backend service.
* **TaskApp Implementation:** Compiled with JDK 25 and running on a custom stripped Eclipse Temurin Server JRE 25 generated via `jlink`, enabling Project Loom virtual threads and modern language idioms (Records, Pattern Matching).
* **References:** [backend/README.md](../backend/README.md), [System Design Document § 2 (ADR-001)](System%20Design%20Document.md#adr-001-modern-java-25--project-loom-virtual-threads-over-reactive-webflux)

#### Java Record (DTO)
* **Definition:** A transparent, immutable carrier class introduced in modern Java that automatically provides canonical constructors, getters, `equals()`, `hashCode()`, and `toString()`.
* **TaskApp Implementation:** Used exclusively for all API request and response Data Transfer Objects (DTOs) such as `TaskResponse`, `CreateTaskRequest`, and `AuthResponse`.
* **References:** [System Design Document § 4.3](System%20Design%20Document.md#43-backend-service-architecture-backend), [backend/README.md](../backend/README.md)

#### Jenkins Declarative Pipeline
* **Definition:** A structured, version-controlled DSL for authoring Jenkins CI/CD automation pipelines within a `Jenkinsfile`.
* **TaskApp Implementation:** Defined in `deploy/jenkins/pipeline/Jenkinsfile.podman` and `deploy/jenkins/pipeline/Jenkinsfile.k8s` to automate JDK 25 testing, container packaging, Podman Compose smoke tests, and Kubernetes Kustomize rollout.
* **References:** [deploy/jenkins/README.md](../deploy/jenkins/README.md), [System Design Document § 7.3](System%20Design%20Document.md#73-jenkins-cicd-automation-architecture-deployjenkins)

#### jlink (Java Linker)
* **Definition:** A JDK command-line tool that assembles and optimizes a set of modules and their dependencies into a custom, stripped runtime image containing only the necessary components.
* **TaskApp Implementation:** Used in Stage 2 of `backend/Dockerfile` to generate a 63MB headless Server JRE (stripping debug symbols, header files, and unneeded modules), reducing the backend runtime footprint by over 70% and minimizing container attack surface.
* **References:** [System Design Document § 7.1](System%20Design%20Document.md#71-multi-stage-podman--oci-packaging), [backend/Dockerfile](../backend/Dockerfile), [backend/README.md](../backend/README.md#containerization--custom-server-jre-jlink)

#### JWT (JSON Web Token)
* **Definition:** A compact, URL-safe standard (RFC 7519) for transmitting claims securely between parties as a digitally signed JSON object.
* **TaskApp Implementation:** Generated upon successful login in `AuthService` using JJWT with HMAC-SHA256 signatures. The token carries the subject (username), user ID, and role, expiring after exactly 15 minutes to adhere to NIST SP 800-63B standards.
* **References:** [System Design Document § 2 (ADR-005)](System%20Design%20Document.md#adr-005-stateless-jwt-architecture-with-nist-sp-800-63b-compliance), [System Design Document § 6.1](System%20Design%20Document.md#61-nist-special-publication-alignment)

### K

#### Kanban Board
* **Definition:** An Agile workflow management method and visualization tool where work items are represented as cards progressing horizontally across status swimlanes.
* **TaskApp Implementation:** Interactive UI feature in `frontend/src/app/features/tasks/` supporting drag-and-drop status transitions between `TODO`, `IN_PROGRESS`, and `DONE` via `@angular/cdk/drag-drop` synchronized with the backend REST API.
* **References:** [frontend/README.md](../frontend/README.md), [System Design Document § 1.2](System%20Design%20Document.md#12-core-capabilities)

#### Kubernetes (K8s)
* **Definition:** An open-source container orchestration system for automating application deployment, scaling, and operational management across computing clusters.
* **TaskApp Implementation:** Manifests located in `deploy/k8s/` orchestrating pods, services, ingress, and stateful storage across dev and prod environments.
* **References:** [deploy/k8s/README.md](../deploy/k8s/README.md), [System Design Document § 7.2](System%20Design%20Document.md#2-kubernetes-cloud-native-manifests-deployk8s)

### L

#### Liveness & Readiness Probes
* **Definition:** Kubernetes diagnostic mechanisms: a *readiness probe* determines when a container is ready to accept incoming traffic, while a *liveness probe* detects deadlocks and triggers automated container restarts.
* **TaskApp Implementation:** Configured on the Spring Boot backend deployment targeting `/actuator/health/readiness` (verifies DB connection) and `/actuator/health/liveness`.
* **References:** [System Design Document § 7.2](System%20Design%20Document.md#2-kubernetes-cloud-native-manifests-deployk8s), [deploy/k8s/README.md](../deploy/k8s/README.md)

### M

#### Maven Wrapper (`mvnw`)
* **Definition:** A script and companion jar bundled inside a project repository that allows Apache Maven builds to run consistently without requiring a pre-installed Maven binary on the host machine.
* **TaskApp Implementation:** Present in `backend/mvnw` and `backend/mvnw.cmd` pinned to Apache Maven 3.9.x to ensure reproducible backend builds across developer workstations and CI/CD agents.
* **References:** [backend/README.md](../backend/README.md#the-maven-wrapper-mvnw-guide)

#### MVCC & `READ COMMITTED`
* **Definition:** Multi-Version Concurrency Control (MVCC) is PostgreSQL's mechanism for handling concurrent transactions where readers do not block writers and writers do not block readers. `READ COMMITTED` is the default transaction isolation level.
* **TaskApp Implementation:** Configured across the `app_db` database, ensuring queries see data committed before the query began without dirty reads.
* **References:** [Data Dictionary § 1.2](Data%20Dictionary.md#12-database-engine--server-configuration)

### N

#### NGINX 1.27 Alpine
* **Definition:** A high-performance, event-driven HTTP server and reverse proxy container running atop a lightweight Alpine Linux distribution.
* **TaskApp Implementation:** Deployed as the edge front door (`taskapp-web`) serving Angular static assets, enforcing security headers, executing gzip compression, and proxying `/api/*` and `/actuator/*` traffic to the backend.
* **References:** [System Design Document § 2 (ADR-003)](System%20Design%20Document.md#adr-003-nginx-alpine-edge-reverse-proxy--static-host), [frontend/nginx/nginx.conf](../frontend/nginx/nginx.conf)

#### NIST SP 800-53
* **Definition:** A publication by the National Institute of Standards and Technology defining Security and Privacy Controls for Federal Information Systems and Organizations.
* **TaskApp Implementation:** Satisfies controls **AC-12** (Session Termination via 15-min JWT timeouts), **AC-10** (Concurrent Session Control), **AC-3** (Access Enforcement via SpEL ownership rules), and **SC-8** (Transmission Protection via TLS and security headers).
* **References:** [System Design Document § 6.1](System%20Design%20Document.md#61-nist-special-publication-alignment)

#### NIST SP 800-63B
* **Definition:** NIST Digital Identity Guidelines covering authentication and lifecycle management controls.
* **TaskApp Implementation:** Adheres strictly to § 7.2 (15-minute maximum session inactivity timeout) via 900,000 ms JWT token expiry, and § 7.2.1 (immediate user-initiated session termination on logout).
* **References:** [System Design Document § 6.1](System%20Design%20Document.md#61-nist-special-publication-alignment), [System Design Document § 2 (ADR-005)](System%20Design%20Document.md#adr-005-stateless-jwt-architecture-with-nist-sp-800-63b-compliance)

### O

#### Offline Sandbox / Mock Mode
* **Definition:** A resilient frontend architecture pattern where the client application falls back to an in-memory client-side data store when backend services are unavailable.
* **TaskApp Implementation:** Embedded in `AuthService` and `TaskService`, enabling full UI demonstration and testing with pre-populated mock tasks if the Spring Boot API is down or in isolated environments.
* **References:** [System Design Document § 2 (ADR-006)](System%20Design%20Document.md#adr-006-dual-mode-frontend-client-live-api--resilient-mock-sandbox), [frontend/README.md](../frontend/README.md)

#### Open-Session-In-View Anti-Pattern (`open-in-view: false`)
* **Definition:** A pattern that keeps a database persistence context open during the entire HTTP request lifecycle, often leading to connection pool exhaustion and hidden N+1 queries during view rendering.
* **TaskApp Implementation:** Disabled explicitly via `spring.jpa.open-in-view: false`. Hibernate sessions and database connections are opened and released strictly within `@Transactional` service methods.
* **References:** [System Design Document § 5.4](System%20Design%20Document.md#54-hikaricp--hibernate-configuration-tuning)

---

### P

#### PersistentVolumeClaim (PVC)
* **Definition:** A Kubernetes API request for durable storage of a specified size and access mode, bound to a physical PersistentVolume (PV).
* **TaskApp Implementation:** Defined in `deploy/k8s/base/postgres/postgres.yaml` to ensure PostgreSQL database state in `pgdata` persists across container redeployments and pod rescheduling.
* **References:** [deploy/k8s/README.md](../deploy/k8s/README.md), [System Design Document § 7.2](System%20Design%20Document.md#2-kubernetes-cloud-native-manifests-deployk8s)

#### PostgreSQL 18
* **Definition:** A robust, open-source object-relational database management system known for reliability, strong ACID compliance, and advanced extensible features.
* **TaskApp Implementation:** Operates as the core database container (`postgres_db`), housing the partitioned `tasks` schema and custom ENUM types.
* **References:** [Data Dictionary](Data%20Dictionary.md), [database/README.md](../database/README.md)

#### Principle of Least Privilege (PoLP)
* **Definition:** A foundational information security principle requiring that users and application accounts are granted only the minimum permissions necessary to perform their legitimate duties.
* **TaskApp Implementation:** Demonstrated in the database tier where `spring_boot_user` holds DML permissions (`SELECT`, `INSERT`, `UPDATE`, `DELETE`) but has zero DDL authority (`CREATE`, `DROP`, `ALTER`), preventing SQL injection-based schema alteration.
* **References:** [Data Dictionary § 2](Data%20Dictionary.md#2-role-based-access-control--security-model), [System Design Document § 5.3](System%20Design%20Document.md#53-database-permissions--least-privilege-databasepermissionspermissionssql)

#### Project Loom & Virtual Threads
* **Definition:** A Java platform enhancement that introduces lightweight user-mode threads managed by the JVM runtime rather than 1:1 mapped OS threads.
* **TaskApp Implementation:** Enabled via `spring.threads.virtual.enabled: true` in Spring Boot 4.1.1 on Java 25, allowing blocking JDBC calls to unmount virtual threads from carrier threads, achieving high concurrency (> 2,000 req/sec) without reactive code complexity.
* **References:** [System Design Document § 2 (ADR-001)](System%20Design%20Document.md#adr-001-modern-java-25--project-loom-virtual-threads-over-reactive-webflux), [backend/README.md](../backend/README.md)

#### Podman
* **Definition:** A daemonless, open-source Linux tool for finding, running, building, sharing, and deploying applications using Open Container Initiative (OCI) Containers and Container Images.
* **TaskApp Implementation:** Used as the primary container engine across the repository, enabling rootless container builds and execution without requiring a root background daemon.
* **References:** [README.md](../README.md), [System Design Document § 7.1](System%20Design%20Document.md#71-multi-stage-podman--oci-packaging)

#### Podman Compose
* **Definition:** A container orchestration provider for defining and running multi-container applications through declarative YAML configuration files using Podman.
* **TaskApp Implementation:** Defined in `deploy/podman/docker-compose.yaml` to orchestrate the PostgreSQL container, Spring Boot backend API, and NGINX frontend reverse proxy on an isolated bridge network (`taskapp-net`) with healthcheck sequencing.
* **References:** [README.md](../README.md#run-mode-1-podman-compose), [System Design Document § 7.2](System%20Design%20Document.md#1-podman-compose-deploypodmandocker-composeyaml)

#### Podman Multi-Stage Build
* **Definition:** An OCI container construction method that employs multiple `FROM` instructions to separate compilation environments from the final minimal runtime image without requiring a root daemon.
* **TaskApp Implementation:** The frontend builder (`node:22-alpine`) copies compiled assets into an `nginx:1.27-alpine` runtime (~21MB), while the backend builder employs a 3-stage build: compiling with `eclipse-temurin:25-jdk-alpine`, generating a minimal Server JRE (~63MB) via `jlink`, and deploying into an unprivileged `alpine:3.21` container.
* **References:** [System Design Document § 7.1](System%20Design%20Document.md#71-multi-stage-podman--oci-packaging), [frontend/Dockerfile](../frontend/Dockerfile), [backend/Dockerfile](../backend/Dockerfile)

### R

#### RBAC (Role-Based Access Control)
* **Definition:** A security mechanism where system access and execution rights are granted based on assigned organizational roles rather than individual identity.
* **TaskApp Implementation:** Implemented with roles `USER` and `ADMIN`. The Angular UI hides admin views via `adminGuard`, while Spring Security enforces `@PreAuthorize("hasRole('ADMIN')")` on sensitive user administration endpoints.
* **References:** [System Design Document § 1.2](System%20Design%20Document.md#12-core-capabilities), [System Design Document § 6.2](System%20Design%20Document.md#62-authentication--authorization-flow)

#### Resource-Based Access Control / ABAC
* **Definition:** An authorization approach that evaluates attributes of the requesting user, the target resource, and the action to verify ownership or relationship before permitting operations.
* **TaskApp Implementation:** Enforced in `TaskSecurity.isTaskOwner(taskId, username)`. Standard users can only view, update, or delete tasks they personally created, while administrators retain global management access.
* **References:** [System Design Document § 3.3](System%20Design%20Document.md#33-end-to-end-request--authentication-lifecycle), [System Design Document § 4.3](System%20Design%20Document.md#43-backend-service-architecture-backend)

#### Reverse Proxy
* **Definition:** A proxy server that sits in front of one or more web servers, intercepting and directing client requests to backends while providing caching, security filtering, and load balancing.
* **TaskApp Implementation:** NGINX 1.27 acts as the front door for TaskApp, receiving all port 80/443 traffic, serving compiled Angular static assets, and forwarding `/api/*` and `/actuator/*` traffic upstream to Spring Boot.
* **References:** [System Design Document § 3.1](System%20Design%20Document.md#31-three-tier-cloud-native-architecture), [frontend/nginx/nginx.conf](../frontend/nginx/nginx.conf)

#### RFC 9457 / RFC 7807 (Problem Details)
* **Definition:** An IETF standard specification providing a machine-readable JSON format for reporting errors from HTTP APIs (`application/problem+json`).
* **TaskApp Implementation:** Generated by Spring Boot's `GlobalExceptionHandler` and parsed by Angular's `errorInterceptor` to provide structured details: `type`, `title`, `status`, `detail`, `instance`, and validation errors.
* **References:** [System Design Document § 4.3](System%20Design%20Document.md#43-backend-service-architecture-backend), [backend/README.md](../backend/README.md)

### S

#### Schema Partitioning (`tasks` Schema)
* **Definition:** Grouping related database tables and types inside an explicit named schema namespace within a relational database, separate from the default `public` schema.
* **TaskApp Implementation:** All application tables (`users`, `tasks`) and ENUM types are located inside `tasks`, with the Spring Boot JDBC connection setting `currentSchema=tasks`.
* **References:** [Data Dictionary § 1.1](Data%20Dictionary.md#11-architectural-purpose), [database/ddl/task-schema.sql](../database/ddl/task-schema.sql)

#### SpEL Security Expressions
* **Definition:** Spring Expression Language expressions used within security annotations (e.g. `@PreAuthorize`, `@PostAuthorize`) to evaluate dynamic runtime authorization rules.
* **TaskApp Implementation:** Applied on controller endpoints, e.g. `@PreAuthorize("hasRole('ADMIN') or @taskSecurity.isTaskOwner(#id, authentication.name)")`.
* **References:** [System Design Document § 4.3](System%20Design%20Document.md#43-backend-service-architecture-backend), [System Design Document § 6.1](System%20Design%20Document.md#61-nist-special-publication-alignment)

#### Spring Boot 4.1.1
* **Definition:** An enterprise Java framework providing opinionated auto-configuration, dependency injection, and embedded web servers for microservices.
* **TaskApp Implementation:** The core backend framework orchestrating the REST API (`backend/`), Spring Security, Spring Data JPA, and Actuator endpoints.
* **References:** [backend/README.md](../backend/README.md), [System Design Document § 4.3](System%20Design%20Document.md#43-backend-service-architecture-backend)

#### Spring Data JPA / Hibernate 7
* **Definition:** A data access abstraction layer that implements the Java Persistence API (Jakarta Persistence) via the Hibernate ORM engine to bridge Java domain entities with relational tables.
* **TaskApp Implementation:** Manages persistence for `TaskEntity` and `UserEntity`, executing derived repository queries and enforcing entity validations.
* **References:** [System Design Document § 4.3](System%20Design%20Document.md#43-backend-service-architecture-backend), [Data Dictionary § 1.2](Data%20Dictionary.md#12-database-engine--server-configuration)

#### Standalone Components
* **Definition:** An Angular architecture model introduced in Angular 14+ that allows components, directives, and pipes to be authored without declaring an intermediary `NgModule`.
* **TaskApp Implementation:** 100% of the TaskApp Angular application uses standalone components (`imports: [...]`), reducing boilerplate and optimizing build bundle tree-shaking.
* **References:** [System Design Document § 2 (ADR-002)](System%20Design%20Document.md#adr-002-angular-22-standalone-components-with-reactive-signals-over-ngmodules), [frontend/README.md](../frontend/README.md)

#### StatefulSet
* **Definition:** A Kubernetes controller used to manage stateful applications that require unique pod identities, stable network identifiers, and persistent storage bindings.
* **TaskApp Implementation:** Manages the PostgreSQL database deployment in `deploy/k8s/base/postgres/postgres.yaml`, attaching durable volume storage to pod index 0.
* **References:** [deploy/k8s/README.md](../deploy/k8s/README.md), [System Design Document § 7.2](System%20Design%20Document.md#2-kubernetes-cloud-native-manifests-deployk8s)

### T

#### Task
* **Definition:** The fundamental business domain entity managed by TaskApp, representing an item of work assigned to a user with lifecycle tracking.
* **TaskApp Implementation:** Stored in `tasks.tasks` with fields `id`, `user_id`, `title`, `description`, `status`, `priority`, `due_date`, `created_at`, and `updated_at`.
* **References:** [Data Dictionary § 3.2](Data%20Dictionary.md#32-table-taskstasks-task-items--lifecycle-records), [System Design Document § 5.1](System%20Design%20Document.md#51-relational-schema-databaseddltask-schemasql)

#### Task Priority
* **Definition:** An attribute indicating the urgency and importance of a given task.
* **TaskApp Implementation:** Enforced via custom ENUM `tasks.task_priority` with valid values `'LOW'`, `'MEDIUM'`, and `'HIGH'`. Defaults to `'MEDIUM'`.
* **References:** [Data Dictionary § 2.2](Data%20Dictionary.md#22-custom-user-defined-types-enum-catalog), [database/ddl/task-schema.sql](../database/ddl/task-schema.sql)

#### Task Status
* **Definition:** An attribute representing the operational lifecycle phase of a task.
* **TaskApp Implementation:** Enforced via custom ENUM `tasks.task_status` with valid values `'TODO'`, `'IN_PROGRESS'`, and `'DONE'`. Governs Kanban column placement.
* **References:** [Data Dictionary § 2.2](Data%20Dictionary.md#22-custom-user-defined-types-enum-catalog), [frontend/README.md](../frontend/README.md)

#### Trivy
* **Definition:** A comprehensive and versatile security vulnerability and misconfiguration scanner for container images, file systems, and Git repositories.
* **TaskApp Implementation:** Executed as an automated security quality gate within CI/CD pipelines to inspect container images prior to cluster deployment.
* **References:** [deploy/jenkins/README.md](../deploy/jenkins/README.md), [System Design Document § 7.3](System%20Design%20Document.md#73-jenkins-cicd-automation-architecture-deployjenkins)

### U

#### User
* **Definition:** An entity representing a registered human operator or system account capable of authenticating and managing tasks.
* **TaskApp Implementation:** Stored in `tasks.users` with unique constraints on `username` and `email`, salted password hashes, assigned `role`, and audit timestamps.
* **References:** [Data Dictionary § 3.1](Data%20Dictionary.md#31-table-tasksusers-user-identity--credentials), [System Design Document § 5.1](System%20Design%20Document.md#51-relational-schema-databaseddltask-schemasql)

#### User Role
* **Definition:** The authorization privilege tier assigned to a system user.
* **TaskApp Implementation:** Stored as PostgreSQL ENUM `tasks.user_role` with values `'USER'` (standard self-service permissions) and `'ADMIN'` (global read/write and user management).
* **References:** [Data Dictionary § 2.2](Data%20Dictionary.md#22-custom-user-defined-types-enum-catalog), [System Design Document § 6.2](System%20Design%20Document.md#62-authentication--authorization-flow)

### Z

#### Zoneless Change Detection (`provideZonelessChangeDetection`)
* **Definition:** An experimental, high-performance execution mode in modern Angular that eliminates the runtime overhead and monkey-patching of `zone.js` by relying purely on signals and microtasks for change detection.
